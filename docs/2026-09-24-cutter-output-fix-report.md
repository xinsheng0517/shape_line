# 切割机出口托盘修复交付记录（2026-09-24）

## 结果与原因

已按批准的“单次入机切一级＋出口托盘暂存”方案修复 V3 挑战关切割机。旧自动档在原坯纵切后将两个半块放入内部 `autoQueue`，下个调度周期直接横切；产物从未进入正常出口流程，因此未接传送带也会发生二次切割。`PetalV3.cut()` 本身只切一级，无需更改固定配方。

现在自动档按**本次外部输入**判断：完整原坯纵切一次，半块横切一次，四分之一块拒收。每次加工所得的两个产物分别进入前、侧出口托盘。托盘是输出缓冲，不是输入队列；没有下游时保留原物品，补接合法传送带后各自排出。两侧未排空前不启动下一次加工。原有多功能混合机的内部半块配对逻辑保持不变。

## 验收证据

- 先用原逻辑复现失败：自动档在两个出口都未连接时，纵切所得半块进入内部待切队列，随后开始横切。新增断开出口用例在修复前因输出阶段为 `quarter` 而失败，修复后 T/C/S × 四朝向共 12 组均稳定运行 100 tick，双出口仍为 `vertical-half`，`unitIds` 不重不漏。
- 单侧接通时，仅该侧排出；另一侧保留原物品。加工过程中移除传送带、满载、方向不合法和暂停均由运行时回归覆盖。半块经外部传送带返回合法入口后才开始第二次切割；四分之一块被拒收。
- C1、C2、C5、C6 均用真实的“首次切割→两个半块外运→二级切割→合并→交付”测试路线通关。C1：278 tick、49 带、2 采集、3★；C2：618 tick、62 带、3 采集、2★；C5：304 tick、52 带、2 采集、3★；C6：632 tick、64 带、3 采集、2★。C5/C6 满足采集器≤3、传送带≤80，四关目标与星级线未修改。
- 全部 14 个 `test*.js` 文件通过，`node --check` 检查修改的 JavaScript 通过，`node build.js` 成功生成单文件游戏。浏览器分别打开源码版与构建版，布置无下游切割机可见前、侧暂存托盘；源码版补接单侧传送带后只释放对应产物，两个页面均无控制台错误。480px 宽视口下整张棋盘仍按现有布局缩小，托盘保持分离，但小屏细节可读性仍受全局缩放限制。

## 后续观察

高难关现有内部参考线路可通关但只有 2★；尚未用真人试玩证明三星布线可达。建议在独立的难度平衡工作中寻找更优线路并收集完成率，再决定是否调整星级门槛。本次没有放宽门槛。旧 V3 蓝图文件可加载，若线路依赖原自动档内部双切，玩家需补上外部二级切割线路；系统不会擅自改写已保存布线。
