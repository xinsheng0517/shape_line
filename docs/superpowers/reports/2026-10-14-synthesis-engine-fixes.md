## 已修复反例

1. **自动模式被不完整规则阻断。** 删除 partial posting 等待决策；自动模式只优先尝试已经凑齐的注册规则，其余合法二输入继续通用合成。显式绑定 `ruleId` 才等待该规则；单输入仍为 pending。三输入等待测试改为显式绑定。100,000 条 `T + noise-N` 规则下，`T + C` 自动合成成功，`candidateChecks=0`。
2. **自定义算子只试首组。** 自定义算子在有界候选搜索的叶子验证输出，首组 `slot-conflict` 后继续尝试合法后组。`copy` 算子与 `T×2` 规则对 `[T@TL,T@TL,T@BL]` 在有序、无序、自动和显式选择中均成功。`select(...,{maxCandidates})` 默认预算 10,000，覆盖索引展开、候选检查、约束回溯及通用配对；预算不足返回 `budget-exceeded`，不伪装成无配方。身份重复、来源冲突和物料守恒校验继续保留。
3. **规划切割不是可执行的二路切割。** 几何分解和闭包边均使用纵向或横向二分，`step.mode` 明确为 `vertical/horizontal`，`outputs` 精确记录两个非空分区及余料。四槽原坯到单槽需连续两次切割。测试逐步检查轴向、分区、总量和物理 ID 守恒。原有 `raise-full` 再切割回归仍在 `maxDepth=3,maxStates=300` 内通过，没有删除或放宽该断言。
4. **递归笛卡尔积绕过工作预算。** 规划在递归展开、规则检查和需求选择阶段计入工作预算；预筛当前节点能否参与规则，并消除相同无序需求的对称组合。`C count:30`、来源 `[T@TL,C@TL,C@BL]`、目标第二层 `TR:T`、`maxStates=20,maxDepth=2` 的反例在 2 秒子进程超时保护下正常返回 `budget-exceeded`，`visited<=20`。
5. **虚拟来源和步骤身份不一致。** 虚拟化按原 `sourceId` 分组，保留 `sameSource` 条件；单输入步骤沿用节点身份，二输入以上复用供应时将完整前驱图一致重映射。测试覆盖同来源四单元提升、连续两次提升的前步输出/后步输入 ID 相同，以及带前驱变换的二输入规则消费同一批物料。

## 扩展能力与索引

- 规范化单元增加 `originKind`，来源一致性依据原始材质；自定义算子可把 `shapeKind` 改为已注册材料，但必须严格保留 `id/sourceId/originKind`。伪造原始材质、未知输出材料、增减单元仍拒绝。
- 声明式 `operation:'transform', output:{material:'Z'}` 先执行自动几何合并，再修改现有单元的当前材料。覆盖一输入原坯变材、不同材质多输入变材、后续再合成以及变材路径规划。存在变材扩展时，规划不会提前按源材质缺失宣布不可达。
- `enabled:false` 的规则保留在配置中，但不进入匹配索引。显式调用返回 `rule-disabled`；重新注册启用后生效，注册与导入继续更新 revision 并失效缓存。
- 通配规则按输入数分桶，combine 只读相同输入数，select 排除输入数超过当前池的桶；规则排名结果缓存，注册变更失效。精确匹配继续走材料 trie/精确桶。

## 边界

任意条件和任意自定义算子不能保证常数匹配成本；预算超限会明确报告，调用方可以增大预算重试。预算约束引擎搜索工作，无法抢占扩展自行写入的同步无限循环。路径搜索是结构级、有工作和深度预算的规划，不把超限等同不可达。切割轴当前对应游戏的 TL/BL/TR/BR 布局；自定义其他布局不会生成无对应实际分区的切割边。

## 独立复核后的补充修复

独立审查新增的来源语义问题已先加入失败回归再修复：

- **切割兄弟被当成独立补给。** 多输入规划先以共享 unit/source 映射实例化完整前驱图，去重共用切割步骤。可消费物料账本检查每个输入确实仍可用，禁止在两条冲突分支重复消费原坯；冲突分支需要独立补给时，重新分配来源，不能冒充同源。`T4` 单原坯纵切两半后触发二输入 `sameSource:true` 提升规则，在原 `maxDepth=2,maxStates=10000` 内返回 found；路径只有一次切割，提升输入有四个唯一 unit ID、一个 source ID。显式提供同原坯的两个来源片段也可在深度 1 返回 found；重复使用同一单元不能伪造同源多输入。
- **同形状的来源分区被去重丢失。** 规划状态键保留规范化的来源分区及 `originKind`，目标比较仍使用纯结构。来源数组先列异源 `T4`、再列同源 `T4` 时，合法同源 unary 提升在原 `maxDepth=1,maxStates=200` 内返回 found。
- **匹配预算没有传递到内部校验。** `select` 与其内部 `combine/matchingRule/pick` 共用预算对象，不再重置到默认 10,000。相同需求桶直接线性选取，不反复增广；普通 `T count:40` 以及 `count:128` 默认可用。`T×20 + wildcard×20` 的 40 输入规则在显式 `maxCandidates:1000000` 下成功，证明高预算传递有效。
- **配置输入数量展开可冻结进程。** `create({maxCompileInputs})` 允许可信 API 配置编译工作预算，默认 1,000,000 个展开需求。注册、初始配置和导入都在每个数量循环前检查剩余工作；同一规则的全部输入及同一次配置批次累计扣减。超限抛出 `configuration-budget-exceeded`，属于资源预算，不表示材料或配方非法。导入暂存注册表后才提交；超限时材料、规则、revision 原子保持。隔离子进程对 `count:1000000000` 的 JSON 导入在 1,500ms 超时保护内正常返回明确错误，原注册表和 revision 均未改变。另覆盖批次累计超限、可信提高预算成功及正常 128 输入。

上述补充完成后的最新运行：engine、performance、petal、synthesis-runtime、v3-runtime 以及三个修改 JS 文件的语法检查全部退出 0。100k 精确规则命中仍为 2 次候选检查，未命中、共享 T 噪声以及输入不足通配规则仍为 0 次；最新 100k 精确命中 median/p95 为 0.0219/0.0289ms，100k 输入不足通配规则为 0.0112/0.0235ms。停止修改，交独立审查复核。

## 跨节点来源关系的最终回归

复核再次暴露：`[x:TL, y:TL, y:BL]` 的前两个单元可见结构相同，局部来源分区也相同；局部规范化仍可能丢掉能与 `y:BL` 配对的 `y:TL`。先加入该失败回归，确认旧实现返回 `budget-exceeded` 后修复：

- 状态去重同时记录稳定的供应来源谱系、单元谱系和物品内部来源分区。虚拟化与复制供应产生的新物理 ID 继承谱系，不直接把不断生成的新物理 ID 用作去重依据；不同根来源、不同根单元保留各自的跨节点关系。
- 多输入候选的前驱图能直接合并且消费账本无冲突时，沿用原规划物料身份。只有复用发生冲突时才克隆供应，避免正常合并后丢失与尚未消费的第三片之间的同源关系。
- 三来源的全部六种排列均返回 found；每条返回路径通过逐步可消费物料账本回放，无重复消费。同源三片中先对 TL/BL 两片提升，再与 TR 第三片合并，在 `maxDepth=2,maxStates=10000` 返回两步路径，最终三个唯一单元、同一个来源，前驱输出与后继输入连续。
