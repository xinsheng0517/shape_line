# 通用合成系统重构设计（已批准）

日期：2026-10-14。范围：当前形状流水线游戏的合成系统、V3 运行时及发行包。状态：用户已通过确认选项批准“任意材质拼接＋重叠自动层叠＋无固定层数上限”方案，进入实现。

## 1. 目标

取消固定材料组合表、同材禁止、固定合成阶段路径与目标配方对机器合成的限制；让产物由输入的空间结构和可配置规则计算得到。新增材料、规则和运算扩展通过注册接口完成，不修改规则引擎内核。

本次“无限制”指不枚举合法材料组合、不设固定材料种类或合成层数上限；仍拒绝伪造物料、重复物理单元、损坏结构以及同一物理单元被重复消费。机器缓存容量和路径搜索工作预算只控制资源与响应时间，不能作为配方不存在的依据，也不能截断/丢弃物料。

## 2. 方案比较与推荐

| 方案 | 能力与取舍 |
|---|---|
| A：结构运算＋可注册规则（推荐） | 根据槽位/层几何关系拼接和叠层；配置覆盖特殊配方，支持任意材料和新增运算；无需枚举所有产物 |
| B：把固定表改为 JSON 配方表 | 易实现和管理，但每种新组合仍须登记，不能满足自由探索任意组合的目标 |
| C：所有合成都实时图搜索 | 灵活，但把组合爆炸带进模拟主循环；不适合作为每次机器加工的基础 |

采用 A。动态路径推导作为独立、有界的规划能力，普通合成不等待路径搜索。

## 3. 已批准的默认玩法语义

1. 任意已注册材料均可合成，包括同材、不同材、两个原坯、半块、四瓣和已有合成物。
2. 平面位置互补时拼接为同一层；存在位置重叠时，默认把后输入整体放到能够容纳它的最低层，保留输入内部的层间关系。默认不设固定层数上限，不截断高层。
3. 两个物理入口继续使用；规则引擎可一次匹配三、四个及更多输入，机器从多个到达批次中凑齐相应输入，不能把“多输入”只做成不可从游戏触发的 API。
4. 顺序敏感的层叠明确使用 A 为下、B 为上；同一入口多件按到达顺序。平面拼接是无序匹配；规则可配置是否考虑输入顺序。
5. 关卡目标只影响枢纽交付判断与可选的配对优先级，不决定材料能否进入机器、能否合成或是否自动销毁。
6. 默认不自动回收非目标瓣；玩家通过垃圾桶处理不需要的产物。原先依赖目标自动回收的线路可能需要补排废料，不能声称所有旧布线都无需调整。
7. 现有四关目标结构、已有合法配方、存档成绩和蓝图布局可继续使用。旧 half/final 模式作为兼容别名读取，UI 给出新语义说明，不以旧阶段白名单限制合法几何组合。
8. 经典教程、自由、每日及 C3/C4 保持原有教学和计时行为；通过适配层保留已有成功的合成场景，避免把 V3 物理身份模型强行套入旧数组模拟。

平面拼接作为可选机器模式保留，重叠时保留输入并说明位置冲突；默认采用上述自动拼接与层叠。

## 4. 结构模型与核心边界

- **形状定义**：`layers` 按底到顶排列，每层为槽位→材料标识的映射。槽位集合和旋转映射由布局配置定义，游戏初始使用 TL/BL/TR/BR 四槽，引擎不解析材料 ID 的字符位置。
- **物理物料**：保留不可变 `units`、唯一 `unitIds` 和来源身份；每个单元带实际槽位与层号。预览定义不拥有生产身份，不能投入机器。
- **结构签名**：以排序后的布局、层、槽位和完整材料 ID 生成无歧义 canonical key；不得用字符串直接拼接造成多字符材料碰撞。
- **结构与身份分离**：缓存只保存结构运算计划，不缓存带 sourceId 的生产输出对象。每次运算从本次输入构造结果，避免不同批次共用物理单元。
- **旋转与切割**：明确适配器的局部/世界坐标约定，合成比较前统一坐标；多层产物必须能正确旋转、按槽位切割并保持各层物料守恒，不能仅在绘制时模拟层级。
- **兼容门面**：保留 PetalV3.raw/cut/merge/preview/isFinished 调用入口。旧 H_TC、F_TC_TS 等 ID 解析为结构目标，不能成为合法合成的白名单。

## 5. 可配置规则接口

计划新增独立的 `js/synthesis-engine.js` 与 `js/synthesis-config.js`，并通过门面接入现有游戏。

| 接口 | 合同 |
|---|---|
| createEngine(config) | 创建独立注册表、布局、索引及运算缓存，实例间互不污染 |
| registerMaterial(id, descriptor) | 注册任意非空材料 ID；描述名称、颜色和可配置轮廓；使用 Map 避免特殊键污染 |
| registerRule(definition) | 注册输入描述、数量、顺序、条件、优先级及输出运算；编译索引，立即使相关缓存失效 |
| registerOperator(id, handler) | 扩展模块注册新合成运算；核心统一检查结果格式、物料守恒及输入不变性，不使用 eval |
| synthesize(items, options) | 多输入匹配并返回结构结果和实际消费输入；失败返回可解释原因且不消费输入 |
| select(pool, options) | 从带来源容器的缓存中匹配输入，输出消费计划；提交阶段一次性移除选中输入 |
| matches(item, target) | 结构目标比较，目标注册与合成合法性相互独立 |
| derive(target, options) | 根据已注册操作动态推导路径；返回 found/unreachable/budget-exceeded 三种不同结果 |

材料和声明式规则可通过经过校验的 JSON 配置导入/导出。高级运算通过注册扩展提供，无需编辑引擎源代码；不能把“任意新逻辑”误称为不用编写任何扩展代码。

## 6. 运行时调度

- 合并 queueA、queueB 及旧内部半块缓存的候选视图，记录每件物料的真实来源容器与引用。
- 注册规则先按运算、输入数和可提取的材料/标签签名分桶；精确规则直接索引，通配规则进入明确的回退桶。
- 通用几何拼接以占位掩码/结构键查找互补输入；不得对每个规则重跑全队列组合枚举。
- 缓存内容或规则版本改变时才重建匹配结果；不能每个模拟 tick 对不变的队列重复做全量二重扫描。
- 目标优先级只能改变候选顺序；没有目标相关组合时，任意合法通用组合仍可加工。
- 输出阻塞时保留产物并施加背压。内部缓存同样有可观察的容量与等待状态，不无限囤积材料。
- 更新 occupied/resetMaterial/materialIds/拆除/在途统计和显示，使所有缓存、加工中间态与多层产物均计入物料守恒。
- 将模式切换改为先验证占用，再同时提交当前机器模式与新机器默认值，消除已复现的默认值污染。

## 7. 动态路径推导

路径规划使用规范化结构作为节点，已注册的切割、旋转、拼接和层叠作为边，不预存按材料组合写死的工序链。规划不在每次加工的主循环里执行，采用工作量和深度预算。普通结构运算缓存按结构与规则版本复用；路径规划结果包含虚拟物理身份，按调用生成，避免跨调用共用身份。

预算耗尽必须返回 budget-exceeded，而不是宣称配方不可达。循环规则、重复状态及等价旋转应能终止或被去重。对普通四槽目标优先用分解策略推导，在需要时再进行有界搜索。

## 8. UI、存档和发行

- 多层产物按层呈现并显示层数；仅缩小/遮挡绘制不能隐藏实际层信息，需能查看完整分层结构。
- 材料颜色/轮廓来自注册描述，新增材料不能一律误画成梯形。
- 蓝图导入校验从硬编码模式列表改为注册式校验；旧模式映射显式保留。自定义规则配置单独保存并校验，不直接恢复 WeakSet 生产身份对象。
- 新脚本加入 index.html、build.js 及所有使用 VM 加载生产脚本的测试文件，禁止以依赖缺失回退到旧固定规则而产生假通过。
- 最终同步主 dist、中文单文件及现有嵌套发行副本；更新已有提交 zip，并记录各 HTML 哈希。

## 9. 验收与性能

1. 全部 81 种 T/C/S 四槽组合，包括同材组合，都可结构化制造；测试三/四输入、多字符和新注册材料。
2. 覆盖原坯重组、左右/上下/斜对角互补、重叠层叠、多层再切割/旋转、三次以上连续合成、输入乱序与顺序敏感规则。
3. 重复物理 ID、伪造对象、预览、损坏结构及来源冲突均拒绝；拒绝、暂停、堵塞、重置、拆除不导致未记录丢料或复制。
4. 内部半块与外部半块、A/B 单入口及双入口均能配对；注册三输入规则必须在真实机器调度中触发。
5. 动态注册、替换/禁用规则、配置往返、特殊键、多字符 ID 和缓存失效分别测试。
6. 基准分开记录配方数 R、输入单元数 U、队列数 Q。固定 U 测 10/1000/10000/100000 条精确规则的命中/未命中候选检查数与 median/p95；精确查找候选数不随无关 R 增长。注册成本允许 O(R)，通配规则开销单独报告。
7. 路径规划覆盖可达、不可达、循环、搜索超限；超限不能影响正常模拟或吞料。
8. 保持经典模式回归；V3 参考产线因移除自动回收而需要排废料时，更新实际布线测试并明确记录，不能只删掉失败断言。
9. 源码与单文件均在实际浏览器测试交互、C1 合成和控制台；最终报告真实测试结果和性能数据，不承诺有限测试能数学证明所有未来规则无遗漏。

开发前 19 个既有测试文件基线全部通过。实现后的回归结果、审查修复与发行验证另记于 reports，旧固定规则断言按本设计替换并保留原因。
