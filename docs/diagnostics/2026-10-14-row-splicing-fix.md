# 截图中的上下半块拼接修复

日期：2026-10-14。范围：本次截图及 T/C/S 的 TL＋TR、BL＋BR 拼接。已修复、测试并重新打包。

## 根因与复现

1. 自动调度将入口 A 的全部物料排在入口 B 前，通用 auto 直接选前两个可合成输入。`A=[TL,TL], B=[TR]` 会将两个 TL 叠成两层，留下 TR。边搭边供料时，一侧先通且重复供料，另一侧尚未到达也会提前层叠；新增未绑定配方仍可能被这种通用回退绕过。
2. 截图合并机位于 `(12,4)`、朝右，正前方 `(13,4)` 没有机器。合成产物会留在前出口托盘，后续供料积压；这是正常背压。按图同时接通全部线路，旧代码也能在 tick 28 产出一层上半块；先通上支再接下支则可复现错误两层产物及三十余件积压。

T/C/S 的六种上下行组合本身均可合法合成，故无需再建立材料白名单。

## 最小修复

- `js/challenge-v3.js`：自动模式先在全缓存寻找平面互补片，不因前面有重复片漏掉后面的另一侧。单入口重叠重复片保留等待；没有互补组合时，不同入口仍可自动层叠；显式 stack 及注册规则保留原能力。
- `js/synthesis-engine.js`：`genericMode` 调度提示只改变通用路径，注册算子继续接收机器原始 mode。独立审查发现首次择对调整会把 join 传给依赖 auto 的算子，已补失败回归并修复。
- 合并机出口状态显示“合成完成；前出口未连接，产物待取”，帮助区分合成与运输阻塞。侧栏说明更新为新的等待语义。
